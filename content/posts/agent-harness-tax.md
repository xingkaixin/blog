9 月 17 日，Arena.ai 团队发布 [HarnessTax 评测](https://arena.ai/blog/coding-agents-harness-tax)，测试 7 个模型搭配 Claude Code、Codex 与 Pi 的 21 组组合。每组在 SWE-bench Lite 和 Terminal-Bench 2.0 各 30 题上跑 3 次，按 9 月 1 日直连 API 价统一算账。

这组实测里，同模型换用不同工具底座时通过率接近，单次账单最高却差出 5 倍。比如 Fable 5 在前一项基准上，Pi 平均跑 15.4 轮，Claude Code 跑 15.3 轮，后者通过率只高出 1.1%，单次花费却约是 Pi 的两倍。

原厂工具底座也未必总是胜出。在 6 个 Anthropic 与 OpenAI 模型的 12 组跨基准对比里，9 组最高观测通过率来自非原厂工具。

Sonnet 4.6 在 Codex 跑出 68.9%，高于原厂的 66.7% 且费用相近；GPT-5.6 Sol 在后一项基准里跑进 Pi 拿到 83.3%，高过 Codex 的 78.9%，单次成本从 0.76 美元降到 0.42 美元。

## 差价来自 Harness 税，不只是模型单价

要看清差价来源，得先分清界面、模型和 Harness 这三层。Theo 在 10 月 23 日的[拆解](https://x.com/theo/status/2113424203345265053)里指出，模型只生成文本，终端或桌面软件只是界面，提供工具、定义格式并回传结果的那层软件才是 Harness，它也能装进别的应用界面里复用。

报告把工具底座带来的额外开销叫作 Harness 税，首轮请求就已起算。Pi 只带 read、write、edit、bash 四个工具，Claude Code 内置了大量工具与长系统指令，7 个模型平均下来，初始上下文超过 Pi 的 10 倍。

后续每轮都会重发指令、工具定义和历史对话，主会话里全量加载越多源码和日志，每轮冗余上下文的重复账单就越高。

11 月 9 日 Claude 官方博客的[选型指南](https://claude.dev/blog/which-claude-model-should-you-build-with/)引用测算，Opus 5.5 命中前缀缓存时，150K 上下文单轮缓存读取约 0.03 美元，压到 20K 后只要约 0.004 美元。

## 长会话中途直接降档会撞上两条硬约束

长会话跑大模型偏贵，中途改用便宜小模型看似省钱。可 11 月 9 日这篇指南披露的两条接口硬约束，说明会话中途直接降档常常省不出预算，还会弄断推理。

第一条是 Prompt Cache 按模型隔离。缓存只归写入它的模型所有，跨模型不共享，长会话中途把高配大模型换成低价小模型，新模型首轮得按缓存写入价重算整段历史。

第二条是加密思考块（Thinking Block）单向兼容。只有高档模型能向下读取低档模型的思考块，比如 Fable 5.2 能读 Opus 5.5 的记录，低档模型一律读不了高档模型的思考块。

一旦在长会话中途往下换档，尤其从最高档切往低一档模型时，接口会悄悄丢弃读不了的思考块并照常返回成功响应。接手的小模型失去前序推理链，只能盲目接着修改代码。

## 选型算单次解决成本，换档留在会话边界

评估工具底座时不能只看通过率或单价。抽一批仓库真实任务配上可校验结果，放进各自独立会话里实测不同工具底座、模型和推理强度，按接口返回的账单算出单次解决成本再拍板。

需要大模型规划、小模型执行时，优先在独立新会话或子 Agent 边界切换。整项任务交接给低价模型前，带上简短书面计划或工作摘要重开新会话；若必须在同一线程内换档，也得先运行 /compact 压缩历史，绝不在未处理的同一长会话中途直接降档。

![把简短计划交接给新会话，长历史保留在原规划会话中](/posts/images/agent-harness-tax/agent-harness-tax-01.png)

单次任务内需要分担开销，就派发独立上下文的子 Agent。找文件、跑测试和读日志这类容易核对的工作适合交给更便宜的小模型，改代码和关键判断仍留给主模型。

Claude Code 的 opusplan 别名默认 Opus 规划、Sonnet 改代码，启用前先拿真实任务实测比较。

**选型时把工具底座的上下文开销算进单次解决成本，大小模型配合只在独立新会话或子 Agent 边界切换。** 换模型前带上简短计划另开新会话，把文件检索和日志排查留在低价子 Agent 里，长会话中途就地降档省不出预算。
